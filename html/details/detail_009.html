为什么开源对人工智能很重要

Oreilly.com2026-08-10生成于 2026-08-11 17:42

1995 年，媒体讨论的问题是 Netscape 还是 Microsoft 将控制网络。事实证明，答案都不是。

网景和微软都旨在主导网络服务器和浏览器市场，他们认为，谁控制了连接的两端，谁就拥有了一个互联网“平台”，可以与微软在个人计算机上享有的死亡之握相抗衡。两家公司竞相将他们能想到的所有功能直接构建到产品中，其理论基础是谁构建了集成度最高、功能最齐全的网络服务器，谁就会获胜。

开源 Apache Web 服务器采取了相反的赌注。它仍然是一个具有干净扩展层的网络服务器，因此任何人都可以在其上添加新的东西，而无需征求许可或等待下一个发布周期。几年之内，Apache 无疑是最受欢迎的 Web 服务器，Netscape 的服务器和 Microsoft 的 Internet Information Server (IIS) 也成为历史。人们开始谈论 LAMP 堆栈：Linux、Apache、MySQL 和 (Perl | Python | PHP) 作为合法平台。护城河是模块化，而不是功能。该堆栈的主要元素得以保留，而其他元素已被替换或扩展，这一事实证明了可组合性和分布式创新的力量。

当我在 2004 年撰写有关该模式的文章时，我将这种模式称为“参与架构”。我试图解释那个时代的许可辩论忽略的一个令人不安的事实。我开始使用 Unix 是在System III 的日子里，我们看到了尽管 AT&T 在专有许可下提供 Unix，但它作为一个协作项目是如何取得成功的。几年后，我观察到像 OpenOffice 这样具有整体架构的名义上的开源项目从未建立过太多的社区。我意识到开源不仅仅与许可证有关，还与架构有关。具有标准接口的小内核让人们无需请求许可即可扩展您的工作，这是秘密武器的重要组成部分。

在这个故事中，把 Netscape 和 Microsoft 换成 OpenAI 和 Anthropic，或许你能看到其中的呼应。

模型的个性、默认设置和历史记录过去都存在于您只需稍加努力即可查看和编辑的地方。但他们越来越不这样做了。正如德鲁·布罗尼格（Drew Breunig）前几天向我指出的那样，前沿模型的每个新版本都会将产品的行为从可编辑层移至权重本身，实验室之外的任何人都看不到它，更不用说更改它了。该模型不再是您构建的组件，而是可以根据您的喜好进行调整，并开始成为您租赁的设备。后期培训很重要，但德鲁指出，这也是“以多样性换取可靠性”。对于许多人来说，这是一项很好的贸易，但当我们知道“真正的食物”更好时，这也是为我们提供高度加工食品的贸易。

从大型机到个人电脑再到互联网，每一波计算浪潮都经历了相同的周期：分布式一开始就进行创新，最终的获胜者逐渐关闭其产品以建立护城河。保持市场开放的并不是任何单一组件的许可。当出现更好的组件时，将一个组件更换为另一个组件是多么容易。

连接各部分的协议是该图景的重要组成部分。 Unix 实用程序需要 stdin 和 stdout，而 shell 充当连接它们的一种工具，因此可以轻松构建与现有工具无缝协作的新工具。 shell 和 Unix 实用程序在发明 50 多年之后，如今已成为代理工具的通用语言，这证明了这种方法的强大功能！ TCP/IP、HTTP 和其他互联网协议在保持互联网开放和可组合方面发挥了类似的作用。

幸运的是，到目前为止，我们看到人工智能中可组合的、以协议为中心的架构取得了一些胜利。 Anthropic 的模型上下文协议是朝这个方向的颠覆性举措，它是一个开放标准，允许任何应用程序访问任何工具或数据源，而无需为每个配对进行自定义集成。与其他开放协议一样，MCP 现在在 Anthropic 之外的 Agentic AI 基金会（Linux 基金会的子项目）也有一个家，这至少部分保证了其独立性。

伊索贝尔·摩尔 (Isobel Moure)、伊兰·施特劳斯 (Ilan Strauss) 和我今年早些时候在《协议与权力》(Protocols and Power) 中提出了这样的观点：随着模型商品化，竞争将升级到上下文。开放访问方式无论其下方是开盘权重还是收盘权重，上下文都会打开市场。这是一种从上下文中分离出来的模型，就像 Apache 将 Web 服务器从 Web 应用程序中分离出来一样。

代理技能也可能是开源 AI 未来的关键要素，尽管正如 LAMP 堆栈的历史所示，它们可能会像 Perl 和 PHP 一样被半途而废。那很好。可组合性意味着当更好的东西出现时，或者当更多人同意它时，很容易切换到更好的东西。

Letta、Nous Research 等公司也在便携式存储器领域开展了许多出色的工作。像 Goose 和 Pi 这样的开源代理工具也是将权力还给人们的重要组成部分。 Pi 特别被优化为可修改。有一个有趣的故事，讲述了 Mario Zechner 决定给 Pi 一个“/quit”命令，而不是像 Claude 或 Codex 那样的“/exit”命令。无数的问题和 PR 被提交到 Pi 的仓库，要求或实现“/exit”，但 Zechner 很顽固。他反驳说你应该要求 Pi 将其添加到你的安装中。

但就开源人工智能的规模和范围而言，我上面列出的项目只是冰山一角。  Current AI 的开源差距地图涵盖了超过 24,600 个开源 AI 项目!!，其中 421 个项目在开放性、功能和采用方面进行了深度评分。该映射将堆栈组织为三层：1）模型和关联元素包括数据集、微调工具、VLLM 等推理框架和评估； 2）产品和UX层，包括线束和个人代理； 3) 底层基础设施，包括 PyTorch 等核心 ML 框架、Ollama 等部署工具以及边缘硬件。

当前的人工智能本身是去年巴黎人工智能行动峰会上产生的公私合作伙伴关系。今年夏天，他们宣布了 AI Potluck，他们将其描述为“一个公共项目，旨在构建完全由开源组件组装的垂直集成人工智能产品……这是不属于任何公司或国家的专有人工智能的可行替代方案。”迄今为止，该项目得到了法国政府、DeepMind 和 Salesforce 等科技公司以及奥米迪亚 AI Collaborative、麦克阿瑟基金会和福特基金会等主要慈善机构的 5 年 25 亿美元承诺中约 4 亿美元的支持。

该组织以及 Agentic AI 基金会等其他组织的存在证明了人们对开源 AI 的兴趣不断高涨。相关各方联盟还阐述了很多推动这种兴趣的潜在动机：人工智能主权、企业独立于主要实验室的野心，以及对公共利益技术的兴趣。

还有另一个因素，德鲁·布罗尼格（Drew Breunig）在前几天我们的谈话中指出了这一点。一两个大型封闭模型占主导地位的问题人工智能，以及让这些模型越来越多地将其所需的个性、业务目标和护栏锁定在权重本身中，将会减少作为创新核心的多样性。

德鲁说，我们的工作是让它变得奇怪，故意将模型推离分发范围，而不是满足于实验室默认的结果。他描述了他的团队如何选择不在最近的项目中构建 React，正是出于这个原因：每个模型都已经非常了解 React，因此构建它意味着传递其他人正在做的事情的平均值，而不是真正自己的东西。他开始使用 GLM 和 Kimi 并不是为了省钱，而是因为它们更具可塑性，并且在定制安全带内可以更好地引导方向。他希望开放权重生态系统能够准确生存，以便模型保留基础设施而不是成为设备。

这就是参与架构的真正用途。我们需要将模型、工具和应用程序真正分开，这样那些想要构建一些奇怪的东西的人仍然可以做到这一点，而无需实验室的路线图和护栏来决定他们是否被允许这样做。

“奇怪”可能听起来并不是所有开发人员都想要的。但我们确实在谈论一些非常实用的东西。在上面链接的关于用可靠性换取多样性的短文中，德鲁·布劳尼格 (Drew Breunig) 是这样说的：

实验室必须推出能够提供“足够好”结果的产品当外行给模型一个懒惰的提示时。如果没有方向，模型必须返回一些像样的东西。 （如果它是一个网站，它将使用 Inter 字体、带有单色边框的卡片、渐变，使用 ReAct 和 Tailwind 实现）。 Anthropic 将这个默认输出命名为“分布收敛”。在 CAIS，@trq212 说得很好，粗略地说，“如果它不在你的提示中，你就会得到正在分发的东西”......。较少多样化的模型可以带来更可靠的编码代理，但它们会鼓励输出的单一文化。

我的 O’Reilly AI Codecon 联合主席 Addy Osmani 在阅读了这篇文章的草稿后，将这一点超越了模型多样性：“与我一起工作的几乎没有人在修改权重，但他们正在不断地重写工具及其周围的内容——技能、子代理、钩子、上下文文件等。这就是当前参与的地方。” Addy 继续指出，分叉技能而不是采用默认值，与代理一起旅行的内存和构成文件而不是生活在供应商帐户中，或者故意选择不流行的框架，这些都是易于修改的领域对每个人都很重要。

最后我想回到 Apache 的故事。我相信大型实验室正在犯 Netscape 和 Microsoft 在 90 年代中期所犯的同样的战略错误。是的，让模型对普通用户来说更可靠。但不要关闭那些不为您工作的开发人员的选择，以推动最先进的技术向前发展。正如比尔·乔伊所说几十年前，“无论你是谁，大多数最聪明的人都为别人工作。”任何人都不应该垄断创新，也不应该筑起护城河来阻碍创新。

英文原文全文

In 1995, the question in the media was whether Netscape or Microsoft would control the web. The answer, it turned out, was neither. Both Netscape and Microsoft aimed to dominate the web server and browser market, reasoning that whoever controlled both ends of the connection would have an internet “platform” to rival the deathgrip that Microsoft had enjoyed on the personal computer. The two companies raced to build every feature they could think of directly into the product, on the theory that whoever built the most integrated and full featured web server would win. The open source Apache web server took the opposite bet. It stayed a web server with a clean extension layer, so anyone could bolt something new onto it without asking permission or waiting for the next release cycle. Within a few years, Apache was far and away the most popular web server, and Netscape’s server and Microsoft’s Internet Information Server (IIS) were history. People started talking about the LAMP stack: Linux, Apache, MySQL, and (Perl | Python | PHP) as a legitimate platform. Modularity, not features, was the moat. The fact that major elements of that stack survive while others have been swapped out or extended is a testament to the power of composability and distributed innovation. I called that pattern the architecture of participation when I wrote about it in 2004. I was trying to explain an inconvenient fact that the licensing debates of that era ignored. I had started working with Unix in the System III days, and saw how it had succeeded as a collaborative project even though AT&T offered Unix under a proprietary license. A few years later, I observed that nominally open source projects like OpenOffice with monolithic architectures never built much of a community. I realized that open source wasn’t just about licenses, but about architecture. A small kernel with standard interfaces that lets people extend your work without asking for permission is an important part of the secret sauce. Swap out Netscape and Microsoft for OpenAI and Anthropic in this story, and perhaps you can see the echoes. A model’s personality, its defaults, and its history used to live where you could, with a little effort, see them and edit them. Increasingly, they don’t. As Drew Breunig pointed out to me the other day, each new version of the frontier models moves a little more of the product’s behavior out of an editable layer and into the weights themselves, where nobody outside the lab can see it, let alone change it. The model stops being a component you build with and can adjust to your liking and starts being an appliance you rent. Post-training is important but Drew points out that it is also “trading diversity for reliability.” That’s a good trade for many people, but it is the same kind of trade that gives us highly processed foods when we know that “real food” is better. Every wave of computing, from mainframes to PCs to the internet, has run through the same cycle: distributed innovation at the start, with the eventual winner gradually closing down its offerings to build a moat. What keeps a market open isn’t the license on any single component. It’s how easy it is to swap out one component for another when a better one appears. The protocols connecting the pieces are an important part of that picture. Unix utilities expected stdin and stdout, and the shell acted as a kind of harness to connect them, so it was easy to build a new tool that worked seamlessly with existing ones. A testament to the power of that approach is just how much the shell and Unix utilities are the lingua franca of agentic tooling today, more than 50 years after they were invented! TCP/IP, HTTP, and other internet protocols played a similar role in keeping the internet open and composable. Fortunately, so far, we are seeing some wins for composable, protocol-centric architectures in AI. Anthropic’s Model Context Protocol was a disruptive move in that direction, an open standard for letting any application reach any tool or data source without a custom integration for each pairing. Along with other open protocols, MCP also now has a home outside of Anthropic at the Agentic AI Foundation (a subproject of the Linux Foundation), which is at least a partial guarantee of its independence. Isobel Moure, Ilan Strauss, and I made the case earlier this year in Protocols and Power that as models commoditize, competition moves up the stack to context. Opening the means of accessing that context opens the market, regardless of whether open or closed weights sit underneath it. That’s an unbundling, model from harness from context, done the way Apache unbundled web server from web application. Agentic skills may also be a critical element of the open source AI future, though as the history of the LAMP stack shows, they may fall by the wayside in the same way that Perl and PHP did. And that’s just fine. Composability means that it’s easy to switch to something better when it comes along, or when more people agree on it. There’s also a lot of great work going on in portable memory from players like Letta, Nous Research, and others. Open source agentic harnesses like Goose and  Pi are also a big part of giving power back to the people. Pi in particular is optimized to be modifiable. There’s a fun story told about Mario Zechner’s decision to give Pi a “/quit” command rather than an “/exit” command like Claude or Codex. Countless issues and PRs have been submitted to Pi’s repo, asking for or implementing “/exit”, but Zechner is stubborn. His retort is that you should just ask Pi to add it to your install. But the projects I listed above are just the tip of the iceberg when it comes to the scale and scope of open source AI.  Current AI’s Open Source Gap Map covers more than 24,600 open source AI projects!!, with 421 of them scored in depth across openness, capability, and adoption. The map organizes the stack into three layers: 1) models and associated elements including data sets, fine tuning tools, inference frameworks like VLLM, and evals; 2) the product and UX layer, including harnesses and personal agents; and 3) the infrastructure underneath, including core ML frameworks like PyTorch, deployment tools like Ollama, and edge hardware. Current AI itself is a public-private partnership that came out of the AI Action Summit in Paris last year. This summer they announced AI Potluck, which they describe as “a public project to build a vertically integrated AI product assembled entirely from open source components… a viable alternative to proprietary AI that isn’t owned by any one company or country.” It is backed so far by roughly $400 million of a five-year, $2.5 billion commitment from the French government, tech companies including DeepMind and Salesforce, and major philanthropies including Omidyar’s AI Collaborative, the Macarthur Foundation, and the Ford Foundation. The fact that this organization exists, along with others like the Agentic AI Foundation, is a testament to the rising tide of interest in open source AI. The coalition of interested parties also says a lot about the underlying motivations that are driving that interest: AI sovereignty, corporate independence from the overweening ambition of the major labs, and an interest in technology for the public good. There’s another element, which Drew Breunig put his finger on in our conversation the other day. The problem with having one or two big closed models dominating AI, and having those models increasingly locking their desired personality, business goals, and guardrails into the weights themselves, is that they will reduce the diversity that is at the heart of innovation. It’s our job, Drew said, to make it weird, to push a model deliberately out of distribution rather than to settle for whatever the labs have made the default outcome. He described how his team chose not to build in React for a recent project for exactly that reason: every model already knows React too well, so building in it means shipping the average of what everyone else was doing instead of something genuinely their own. He has started using GLM and Kimi not to save money but because they are more malleable and take direction better inside a custom harness. And he wants the open-weight ecosystem to survive precisely so that models stay infrastructure rather than becoming appliances. That’s what an architecture of participation is actually for. We need real separation between the model, the harness, and the application, so that someone who wants to build something weird can still do it without a lab’s roadmap and guardrails deciding whether they’re allowed to. “Weird” may make it sound like something that not all developers might want. But we’re really talking about something intensely practical. In his short essay on trading reliability for diversity, linked above, Drew Breunig put it this way: Labs have to ship a product that delivers “good enough” results when a layperson gives a model a lazy prompt. Without direction, the model must return something decent. (If it’s a website it’ll use the Inter font, cards with a single colored border, gradients, implemented with ReAct and Tailwind). Anthropic named this default output “distribution convergent.” At CAIS, @trq212 put it well, roughly, “If it’s not in your prompt, you’re getting what’s in-distribution” …. Less diverse models make for more reliable coding agents, but they encourage a monoculture of output. Addy Osmani, my co-chair of the O’Reilly AI Codecon, took this point beyond model diversity after reading a draft of this piece: “Almost nobody I work with is tinkering with weights, but they’re rewriting the harness and what sits around it pretty constantly—skills, subagents, hooks, context files etc etc. That’s where participation is currently happening.” Addy went on to note that forking a skill instead of adopting the default, memory and constitution files that travel with the agent instead of living in a vendor account, or picking the unfashionable framework on purpose are all areas where ease of modifiability matters to everyone. I want to end by returning to the Apache story. I believe that the big labs are making the same strategic mistake that Netscape and Microsoft made in the mid 90s. Yes, make the models more reliable for ordinary users. But don’t shut down the options for developers who don’t work for you to push the state of the art forward. As Bill Joy put it decades ago, “No matter who you are, most of the smartest people work for someone else.” No one should have a monopoly on innovation, and no one should be building a moat to hold it back.
